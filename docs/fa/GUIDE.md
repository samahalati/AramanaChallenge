## ۱. چه چیزی دارید

| بخش | کجا | پورت |
|---|---|---|
| **API** (Django + Django REST Framework) با مستندات Swagger | `backend/` | `8000` (`/api/docs/`) |
| **برنامه‌ی وب** (React + Vite)، پیش‌فرض فارسی با کلید انگلیسی | `frontend/` | `5173` در حالت توسعه |
| **پایگاه‌داده‌ی SQLite** (خودکار ساخته می‌شود) | `data/aramana.sqlite3` | – |

چیز دیگری لازم نیست: نه سرور پایگاه‌داده، نه API پولی، نه کلید API (کلید LLM اختیاری است).

## ۲. پیش‌نیازها

| ابزار | نسخه | بررسی | دریافت |
|---|---|---|---|
| Git | هر نسخه | `git --version` | https://git-scm.com |
| Python | **۳٫۱۱ یا بالاتر** | `python --version` (ویندوز) · `python3 --version` | https://www.python.org/downloads (در ویندوز گزینه‌ی *Add python.exe to PATH* را بزنید) |

## ۳. نصب

```bash
git clone https://github.com/samahalati/AramanaChallenge.git
cd AramanaChallenge

# محیط پایتون
python3 -m venv .venv
source .venv/bin/activate              # macOS / Linux
pip install -r backend/requirements.txt

# بسته‌های فرانت‌اند
cd frontend && npm install && cd ..
```

**ویندوز (PowerShell)** – همان مراحل، با این تفاوت‌ها:
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1             # اگر مسدود شد: Set-ExecutionPolicy -Scope Process Bypass
pip install -r backend\requirements.txt
cd frontend; npm install; cd ..
```
در macOS/Linux یک‌خطی: `make install`.

## ۴. پیکربندی

همه‌چیز مقدار پیش‌فرضِ کارا دارد. برای تغییر، الگو را کپی و ویرایش کنید – `backend/.env` خودکار بارگذاری می‌شود و **هرگز کامیت نمی‌شود**:
```bash
cp backend/.env.example backend/.env      # ویندوز: copy backend\.env.example backend\.env
```

|---|---|---|
| `DEBUG` | `1` | در تولید `0` |

| `ALLOWED_HOSTS` | `*` | نام میزبان‌ها، جداشده با ویرگول |

| `ACCESS_TOKEN_MINUTES` | `60` | مدت اعتبار توکن ورود |
| `MAX_FAILED_LOGINS` / `LOCKOUT_MINUTES` | `5` / `15` | قفل حساب |
| `LLM_PROVIDER` | `none` | `gemini`، `groq` یا `ollama` (بخش ۹) |
| `LLM_API_KEY` / `LLM_MODEL` / `LLM_BASE_URL` | خالی | کلید ارائه‌دهنده، جایگزینی اختیاریِ مدل، جایگزینی اختیاریِ نشانی |
| `DETECTION_CONFIG` | `backend/detection/config.yaml` | وزن‌ها و آستانه‌های موتور تقلب |

## ۵. اجرا

**فقط بار اول – ساخت داده** (schema + سازمان مصنوعی + اولین اجرای تشخیص):
```bash
cd backend
python manage.py migrate
python manage.py seed_demo --detect        # داده‌ی دمو فارسی (پیش‌فرض). انگلیسی: --lang en
```
هر زمان با `python manage.py seed_demo --reset --detect` همه‌چیز را از نو می‌سازید.

**گزینه‌ی الف – توسعه (دو ترمینال)**
```bash
# ترمینال ۱
cd backend && python manage.py runserver 0.0.0.0:8000
# ترمینال ۲
cd frontend && npm run dev                 # باز کنید: http://localhost:5173
```
**گزینه‌ی ب – یک پردازه:** `cd frontend && npm run build` و سپس فقط بک‌اند را اجرا کنید؛ Django برنامه‌ی ساخته‌شده را در **http://localhost:8000** سرو می‌کند.
**گزینه‌ی ج – Docker:** `docker build -t aramana . && docker run -p 8000:8000 aramana` ← http://localhost:8000 (داده هنگام ساخت image ساخته می‌شود).
**گزینه‌ی د – Make:** `make install seed backend` و `make frontend`.

## ۷. کارکرد همه‌چیز

**ورود و مجوزها.** `POST /api/auth/login` یک توکن امضاشده (HS256 JWT) می‌دهد. هر درخواست کاربر را تازه از پایگاه‌داده می‌خواند؛ پس کاربر تعلیق‌شده فوراً قفل می‌شود. دسترسی در دو لایه تعیین می‌شود: **نقش** (`backend/core/rbac.py`: چه نوع کاری) و **رابطه** (کدام رکوردها: خودش، زیردستانِ فعلی، افرادِ نام‌برده‌شده در هشدار). هر چیزی که view اعلام نکرده رد می‌شود. ردها به‌صورت رویداد دسترسی ثبت می‌شوند و خودشان می‌توانند هشدار بسازند. مدیران **هیچ مجوز بالینی ندارند** (تفکیک وظایف) و هیچ‌کس نمی‌تواند هشدارِ مربوط به خودش را ببیند.

**حسابرسی.** خواندن/نوشتن‌های حساس یک ردیف به گزارش حسابرسیِ **زنجیره‌ایِ درهم‌سازی** اضافه می‌کنند (هر ردیف درهم‌سازِ ردیف قبلی را دارد)؛ پس دستکاری آشکار می‌شود: صفحه‌ی حسابرسی «زنجیره تأیید شد» را نشان می‌دهد.

**ماژول الف – منابع انسانی و مدیریت** (`hr`, `accounts`). پروفایل متخصصان، مدارک (با پیگیری انقضا)، قراردادها، چرخه‌ی عمر (در انتظار جذب ← فعال ⇄ تعلیق ← خاتمه؛ هر تغییر دلیل مستند می‌خواهد و تصمیمی انسانی است)، درخت سازمان، تخصیص سوپروایزر با تاریخ اعتبار (تغییر آن، رابطه‌ی قبلی را پایان‌تاریخ می‌دهد)، و نمای **فعالیت و عملکرد** برای هر متخصص (جلسه‌ها، ارجاع‌ها، شاخص‌های کیفیت، حضور در نظارت، توسعه‌ی حرفه‌ای، روندها، هشدارهای مربوط به فرد – فقط تجمیع، بدون محتوای بالینی).

**ماژول ب – نظارت بالینی** (`supervision`, `clinical`). درمانگران جلسه زمان‌بندی می‌کنند (هم‌پوشانی *پذیرفته اما پایش می‌شود*، نه مسدود). سوپروایزرها فقط زیردستانِ فعلی‌شان را می‌بینند: داشبورد (بازبینی‌های معوق، روند)، گردش‌کار بازبینی (در انتظار ← در جریان ← تصمیم ← اقدام‌های اصلاحی ← بستن)، جلسه‌ها، مسائل کیفیت. ارجاعِ یک مسئله‌ی کیفیت یک هشدار قابل‌ردیابی برای انطباق می‌سازد. مراجعان شناسه‌های نام‌مستعارند (`C-0001`)، نه هویت واقعی.

**ماژول ج – تشخیص تقلب و ناهنجاری** (`detection`, `monitoring`).
۱. *داده ← ویژگی:* `monitoring/loaders.py` ردیف‌های پایگاه‌داده را به جدول تبدیل می‌کند؛ خودِ موتور (`backend/detection/`) پایتونِ خالص است و هرگز به Django دست نمی‌زند.
۲. *پنج لایه آشکارساز* (`detection/detectors/`): **قواعد** (هم‌پوشانی، مکان غیرممکن، تأیید سریع یا بدون مستند، انفجار دسترسی ردشده…)، **آمار مقاوم** (مقایسه با همتا)، **Isolation Forest** (پرت‌های چندمتغیره)، **تحلیل گراف** (خوشه‌های انحصاریِ ارجاع/تأیید) و یک **آزمون آگاه از سیاست** که تمرکز ارجاعِ قابل‌توضیح با تخصص را سرکوب می‌کند.
۳. *امتیازدهی* (`scoring.py`): هر شاخص در `config.yaml` وزن دارد؛ امتیاز `۱۰۰ × (۱ − Π(۱ − وزن × قدرت))` است، یعنی دقیقاً مجموع امتیاز شاخص‌هایی که در رابط می‌بینید. سطح‌ها: کم < ۳۵ ≤ متوسط < ۶۰ ≤ بالا < ۸۰ ≤ بحرانی. هشدارهایی که **فقط** شاخص‌های ضعیف (امتیاز ML، حجم) پشتیبانشان است حداکثر «کم» می‌مانند.
۴. *هشدار* شامل شواهد، توضیح، گام پیشنهادیِ تحقیق، نسخه‌ی قواعد/مدل است و میان اجراها deduplicate می‌شود.
۵. *گردش‌کار تحقیق* (فقط انسانی): جدید ← در حال بررسی ← درخواست اطلاعات ← ارجاع ← بسته (بدون اقدام / تأییدشده) یا مثبت کاذب؛ یادداشت جایی که مهم است الزامی است و همه‌چیز در خط زمان و حسابرسی ثبت می‌شود. هیچ امتیاز یا هشداری وضعیت، نقش یا قرارداد کسی را عوض نمی‌کند.
۶. *ارزیابی:* `python manage.py evaluate` دقت/بازیابی/F1، ablation به‌تفکیک لایه و نمونه‌های منفیِ دشوار را نسبت به ground truth مصنوعی می‌سنجد (عددها خوش‌بینانه‌اند چون ناهنجاری‌ها را خودمان نوشته‌ایم – گزارش فنی را ببینید).

**دستیار LLM** اختیاری و مشورتی است – بخش ۹.

**زبان.** پایگاه‌داده انگلیسیِ متعارف نگه می‌دارد؛ متن هنگام نمایش ترجمه می‌شود (هدر `Accept-Language`). برنامه‌ی وب پیش‌فرض فارسی/راست‌به‌چپ با تاریخ جلالی است؛ کلید زبان صفحه را به زبان دیگر بارگذاری می‌کند. جزئیات: [I18N.md](I18N.md).

**داده‌ی مصنوعی.** `seed/generate.py` حدود ۴۷ کاربر، ~۵ هزار جلسه، ارجاع، بازبینی و فعالیت مدیریتی می‌سازد، ناهنجاری‌های الزامی **و موارد بی‌گناهِ شبیه‌به‌آن** (نمونه‌های منفیِ دشوار) را تزریق می‌کند و برای ارزیابی `data/ground_truth.json` را می‌نویسد. ر.ک. [DATASET.md](DATASET.md).

**ساختار فرانت‌اند.** `frontend/src/features/<module>/` برای هر ماژول یک پوشه دارد؛ بخش‌های مشترک `DataTable`، `FormModal`، `Query` (حالت‌های بارگذاری/خطا) و `useAct` (اجرای عملیات، اعلان، تازه‌سازی) هستند. سرور تعیین می‌کند هر نقش چه می‌بیند؛ رابط فقط آن را نشان می‌دهد.

## ۸. استفاده از API

مستندات تعاملی: **http://localhost:8000/api/docs/** (Swagger). از خط فرمان:
```bash
TOKEN=$(curl -s localhost:8000/api/auth/login -H 'content-type: application/json' \
  -d '{"email":"compliance@aramana.test","password":"Demo!2345"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')
curl -s -H "Authorization: Bearer $TOKEN" -H "Accept-Language: fa" localhost:8000/api/alerts?limit=3
```
هدر `Accept-Language: fa|en` زبان عنوان، توضیح و پیام‌های خطا را تعیین می‌کند. گروه‌های اصلی: `/auth/*`، `/hr/*`، `/supervision/*`، `/clinical/*`، `/referrals/*`، `/alerts/*`، `/detection/*`، `/audit/*`، `/meta/*`.

## ۹. دستیار LLM

در صفحه‌ی هشدار، بازبین‌ها (انطباق؛ مدیر پلتفرم برای هشدارهای امنیتی) **تولید خلاصه‌ی تحلیلی** و **بپرس** را دارند. بدون کلید در *حالت قطعی* (بدون شبکه) کار می‌کند: خلاصه‌ی قالبی از روی شواهد. با کلید رایگان از مدل واقعی استفاده می‌کند:

```bash
# backend/.env
LLM_PROVIDER=gemini                    # یا groq یا ollama
LLM_API_KEY=کلید-رایگان-شما            # https://aistudio.google.com/apikey · https://console.groq.com/keys · برای ollama لازم نیست
```
بک‌اند را دوباره اجرا کنید. نشان روی هر پاسخ می‌گوید چه کسی آن را ساخته: مدل (Gemini/Groq/Ollama)، *قالب قطعی*، یا *قالب قطعی (جایگزین)* یعنی مدل شکست خورد یا یک بررسی پاسخش را رد کرد (با «جزئیات» دلیل را ببینید).

مدل ایمنی در یک پاراگراف: مدل فقط شواهدِ نام‌مستعار با شناسه‌های قابل‌ارجاع را می‌بیند؛ پرامپت مجازات/اتهام را ممنوع می‌کند و می‌گوید پرسش‌های تصمیم‌خواه، هویتی و نامرتبط را رد کند؛ هر پاسخ باید از بررسی‌های قطعی (شکل JSON، ارجاع‌های موجود، اعداد موجود در شواهد، نبودن ایمیل/مراجع/نام) **و** یک تماس دوم LLM در نقش قاضی (لحن، سازگاری با سطح ریسک) بگذرد؛ اگر قاضی حکمی ندهد پاسخ نمایش داده نمی‌شود. چیزی را تغییر نمی‌دهد، سقفش ۳۰ درخواست در ساعت برای هر کاربر است و هر گفت‌وگو حسابرسی می‌شود. طراحی کامل و اندازه‌گیری‌های صادقانه: [LLM_ASSISTANT.md](LLM_ASSISTANT.md).

## ۱۰. برگه‌ی دستورها

| دستور (از `backend/`) | کار |
|---|---|
| `python manage.py migrate` | ساخت/به‌روزرسانی schema پایگاه‌داده |
| `python manage.py seed_demo [--reset] [--detect] [--lang fa\|en] [--seed-value N]` | ساخت داده‌ی مصنوعی (اختیاری: پاک‌کردن اول / اجرای تشخیص بعد) |
| `python manage.py run_detection` | اجرای موتور تشخیص (idempotent) |
| `python manage.py evaluate [--write file.json]` | precision/recall/F1 نسبت به ground truth |
| `python manage.py evaluate_llm [--live] [--alerts N]` | red-team محافظ‌های LLM (`--live` با کلید شما) |
| `python manage.py export_docs` | بازتولید `docs/RBAC_MATRIX.md` و `docs/openapi.yaml` از روی کد |
| `python -m pytest -q` | اجرای ۹۳ تست |
| `python scripts/multi_seed_eval.py 1 2 3 4 5 6 7 8` | پایداری در دنیاهای مصنوعی مختلف |

فرانت‌اند (از `frontend/`): `npm run dev` · `npm run build` · `npm run check:i18n` · `BASE=http://localhost:5173 node e2e/smoke.cjs` (تست دود مرورگر؛ نیاز به Playwright).

## ۱۱. عیب‌یابی

| نشانه | علت ← راه‌حل |
|---|---|
| هشدارهای `EBADENGINE` و سپس `'node:util' does not provide an export named 'styleText'` | Node قدیمی است ← Node 22 LTS (یا 20.19+) نصب کنید، ترمینال را ببندید و باز کنید، `frontend/node_modules` را پاک کنید و دوباره `npm install` بزنید |
| `python` / `pip` پیدا نمی‌شود یا نسخه‌ی اشتباه است | از `python3` / `py -3` استفاده کنید؛ در ویندوز Python را با *Add to PATH* دوباره نصب کنید |
| PowerShell اجازه‌ی `Activate.ps1` نمی‌دهد | `Set-ExecutionPolicy -Scope Process Bypass` و دوباره فعال‌سازی |
| `ModuleNotFoundError: No module named 'django'` | محیط مجازی فعال نیست (دنبال `(.venv)` در خط فرمان بگردید) ← فعالش کنید و `pip install -r backend/requirements.txt` را دوباره بزنید |
| صفحه باز می‌شود اما خطا/خالی است | بک‌اند اجرا نیست یا داده ندارد ← `runserver` را بزنید و `seed_demo --detect` را اجرا کنید |
| `Address already in use` | پردازه‌ی دیگری از پورت استفاده می‌کند ← آن را ببندید یا `runserver 0.0.0.0:8001` (و پروکسی را در `frontend/vite.config.js` عوض کنید) |
| بعد از چند تلاش ورود ناموفق است | قفل حساب (۵ شکست، ۱۵ دقیقه) ← صبر کنید یا `seed_demo --reset` |
| دستیار «قالب قطعی» نشان می‌دهد | `LLM_PROVIDER`/کلید در `backend/.env` نیست یا بک‌اند دوباره اجرا نشده |
| دستیار مدام «جایگزین» نشان می‌دهد | محدودیت نرخ یا بار زیاد سطح رایگان (۴۲۹/۵۰۳): دوباره تلاش می‌کند و بعد امن جایگزین می‌شود؛ کمی بعد دوباره امتحان کنید |
| `429` روی دستیار | سقف ۳۰ درخواست در ساعت برای هر کاربر |
| متن انگلیسی در رابط فارسی | زبان در مرورگر ذخیره می‌شود؛ از کلید EN/فا استفاده کنید؛ برای *داده‌ی* دمو با `--lang fa` دوباره seed کنید |
| `npm run check:i18n` شکست می‌خورد | یک متنِ `t("…")` ترجمه‌ی فارسی در `frontend/src/lib/fa.js` ندارد |

## نکات تولید
`DEBUG=0`، یک `SECRET_KEY` طولانی و تصادفی، `ALLOWED_HOSTS` واقعی، PostgreSQL، پایان‌دادن TLS در یک reverse proxy، و اجرای `gunicorn config.wsgi -b 0.0.0.0:8000` (Dockerfile همین کار را می‌کند). احراز هویت اینجا در حد دمو است (رمز محلی، بدون MFA/SSO)؛ فهرست کامل محدودیت‌ها در گزارش فنی است.
